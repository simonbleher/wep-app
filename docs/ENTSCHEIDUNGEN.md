# Entscheidungen

| Datum | Entscheidung | Grund |
|-------|--------------|-------|
| 2026-10-16 | PWA statt nativer Apps | Eine Codebasis für Handy, Tablet und Windows |
| 2026-10-16 | WEP intern als JSON, Excel nur beim Export | Vorlage ist komplex und auf der Parzelle nicht bedienbar |
| 2026-10-16 | Eine Datei pro Rolle (grün/bau) beim Sync | Keine Schreibkonflikte zwischen Bau- und Grün-Wertermittler |
| 2026-10-16 | Vorlage bereinigt (externe Verknüpfung, 54 tote Namen entfernt) | Externe Datei existiert auf anderen Rechnern nicht |
| 2026-10-16 | Preise sind Vorschläge, Regeln nur Warnungen | Wertermittler dürfen nicht eingeschränkt werden |
| 2026-10-16 | Schema für data/katalog.json: eine Position hat entweder ein einzelnes Feld `hoechstwert` oder ein Array `varianten` (Differenzierung nach Form/Alter/Größe/Material/Ausführung), nie beides. Felder `arten` (Beispielpflanzen) und `relevanz` (1–5) ergänzt. Invasive Arten in separater data/invasive.json. | Die Richtlinie gibt teils Einzelpreise, teils Preismatrizen (z. B. Obstgehölze nach Form × Alter) vor; ein einheitliches Varianten-Modell bildet beides sauber ab und bleibt für Suche/Sortierung (K2) und Erfassung (A2) nutzbar. Zwei Druckfehler der Quelle (75;00 €, Aufnahmejahr 2027) wurden dokumentiert in data/README.md übernommen. |
| 2026-10-16 | Framework/Stack für die PWA: React + TypeScript + Vite + vite-plugin-pwa (Workbox) + idb | Vite liefert einen schnellen Dev-Server, schlanke Builds und erstklassige PWA-Unterstützung. React ist die am weitesten verbreitete Bibliothek, vertraut für ein formularlastiges UI und erleichtert die Zusammenarbeit mehrerer Agenten. vite-plugin-pwa erzeugt Service-Worker/Offline-Precaching und das installierbare Manifest ohne Handarbeit. idb ist ein dünner, typsicherer Wrapper um IndexedDB. Gegen reines Vanilla-TS spricht der hohe Boilerplate-Aufwand für reaktive Formulare, gegen Svelte die geringere Team-Vertrautheit. |
| 2026-10-16 | Beta nur für einen Nutzer (Grün); Sync über privates OneDrive (App-Ordner), kein Bau-Teil in der App; Export führt Bau-Excel + Grün-Daten zusammen | Testphase: schnell nutzbar ohne BV-Admin, App-Registrierung oder Rollenabgleich; Bau-Wertermittler arbeitet unverändert in Excel |
| 2026-10-16 | K2-Unit-Tests mit **Vitest**; dazu vorläufig ein minimales Platzhalter-`package.json` + `tsconfig.json` mit ausschließlich `vitest` + `typescript` als devDependencies | A1 (app-gruen/grundgeruest) erstellt parallel das endgültige Grundgerüst (Vite/PWA). Damit K2 eigenständig testbar bleibt, wurden die Testabhängigkeiten bewusst auf vitest + typescript beschränkt; die Dateien werden später mit A1 zusammengeführt. |
| 2026-10-16 | **Export (E1): JSZip + direktes XML-Patching statt ExcelJS oder SheetJS.** ExcelJS und SheetJS haben bekannte Probleme mit komplexen XLSX-Dateien: ExcelJS rebuild fehlt Stile, SharedStrings und Formeln nach dem Roundtrip; SheetJS (Community-Edition) überschreibt Formate und kann merged-cell-Referenzen verlieren. Da wir ausschließlich bestimmte Input-Zellen befüllen (Außenanlagen, Aufwuchs, Formalien) und alle anderen Blätter – besonders die Bau-Blätter – byte-gleich erhalten müssen, ist direktes XML-Patching am sichersten: XLSX ist ein ZIP, wir öffnen mit JSZip, lesen nur die betroffenen Worksheet-XMLs, ersetzen einzelne Zellen per Regex (mit negativem Lookbehind für self-closing Tags), schreiben sie zurück. Bau-Blätter werden nie geöffnet. calcChain.xml wird entfernt; Excel/LibreOffice baut sie beim Öffnen neu auf. Inline-Strings (t="inlineStr") statt Shared-Strings, damit sharedStrings.xml unverändert bleibt. | Die Alternative (ExcelJS) wurde in einem Proof-of-Concept gegen die WEP_Vorlage.xlsx getestet und zerstörte Formeln in verbundenen Zellen. SheetJS Pro wäre sicherer, ist aber kostenpflichtig. JSZip ist MIT-lizenziert und läuft vollständig im Browser. |
| 2026-10-16 | K2 Review-Nachbesserungen: (1) neues optionales Feld `synonyme` (Array von Strings) in `data/katalog.json` + Schema + Suche (Gewicht wie `arten`); (2) Invasiv-Prüfung vergleicht nur noch den GANZEN Namen (exakt/Präfix, enger Tippfehler ≤ `floor(len·0,12)`, max. 2 Edits), kein Einzelwort-Fuzzy mehr; (3) Mindest-Trefferqualität `MIN_QUALITAET = 0,7` verwirft schwaches Fuzzy-Rauschen in der Suche. | (1) Alltagsbegriffe wie „Regentonne“/„Gartenweg“/„Komposter“ lieferten vorher keine Treffer, weil nur Bezeichnung/Kategorie/Arten durchsucht wurden. (2) Mehrwortiger Name wie „Japanischer Staudenknöterich“ matchte fälschlich „Japanischer Hopfen“ über das geteilte Wort „Japanischer“ – ein falscher Invasiv-Hinweis ist schlimmer als keiner. (3) Schwache Fuzzy-Treffer (2 Edits) wie „Tulpen“→Einfriedung/„Türen“ oder „Rasen“→„Rose“ leckten in die Trefferliste; die Schwelle 0,7 trennt sie sauber von legitimen 1-Edit-Treffern (z. B. „Ligustar“→Liguster, 0,72). |
| 2026-10-17 | Export entfernt die Zwischenwerte (`<v>`) von Formelzellen in den Grün-Blättern und Deckblättern | LibreOffice ignoriert `fullCalcOnLoad` in der Standardeinstellung und zeigte sonst alte Summen (0 €); Formelzellen ohne Zwischenwert werden von Excel und LibreOffice immer berechnet. Echte Bau-Blätter bleiben byte-gleich. |
| 2026-10-17 | Sync: MSAL.js mit Authority `consumers` und nur `Files.ReadWrite.AppFolder`; eine JSON-Datei pro WEP mit Hülle `wep-sync/1`; Warteschlange über Store `syncMeta` (lokal geändert nach letztem Abgleich); Konflikt: neuere Änderung gewinnt, ältere als `.konflikt-<Zeit>.json`; Löschen nicht synchronisiert (Marke `geloescht`) | Minimale Rechte, keine Secrets, robust offline; nichts geht verloren; Löschen über Geräte hinweg wäre in der Beta riskanter als nötig |
| 2026-10-17 | **Skizze (S1): SVG-Zeichenfläche, kein Drittanbieter-Canvas-Framework; Datenformat als diskriminierte Union (`SkizzeElement`) in `src/skizze/types.ts`; PNG-Export über Browser-Canvas-API (`skizzeAufContext` + `skizzeAlsPng`); `SkizzeDaten` in `src/model/types.ts` re-exportiert statt dupliziert.** Alternativen betrachtet: Fabric.js/Konva.js (zu groß, eigenes Datenmodell nicht JSON-first), roughjs (handgezeichneter Stil passt nicht zum Lageplan-Charakter). SVG ist native im Browser, benötigt keine Bibliothek, lässt sich mit Pointer Events touch-tauglich bedienen und ist für diese Skizzen-Komplexität ausreichend. Der Undo-Stack speichert vollständige Element-Listen (Snapshot-Ansatz), weil bei Freihand-Zeichnung das Command-Pattern zu aufwendig ist und der Speicherbedarf bei ≤ 50 Schritten vernachlässigbar bleibt. Keine eigene Teststrategie für jsdom/happy-dom nötig: die reine Rendering-Logik (`skizzeAufContext`) ist von der DOM-abhängigen Blob-Erzeugung getrennt und mit einem Mock-Kontext testbar. | Schlank halten (lt. Aufgabenstellung vorläufige Lösung); keine externen Laufzeit-Abhängigkeiten; alle Qualitätsprüfungen (npm test, tsc, build) müssen grün sein. |
| 2026-10-17 | **A2 Katalog-Typen: `@/katalog`-Typen statt `@/model/katalog`-Typen für Katalog-Positionsdaten in WepDetail und regelhinweise.ts** | `sucheKatalog` und `istInvasiv` aus `@/katalog` erwarten den lokalen `Position`-Typ aus `@/katalog/types.ts` (`varianten?: Variante[]`, optional). `@/model/katalog.ts` modelliert dasselbe als diskriminierte Union (`KatalogPositionEinzel | KatalogPositionVarianten`), bei der `varianten` im Varianten-Fall Required ist. Beide repräsentieren dieselben JSON-Daten, sind aber für TypeScript strukturell inkompatibel. Da alle Katalog-Operationen über `@/katalog` laufen, werden auch dort die Typen bezogen. |
| 2026-10-17 | **A2 Preisvorschlag-Staffel**: sehr gut 100 %, gut 75 %, mittel 50 %, schlecht = 1,00 € Festpreis | Übernahme aus `ZUSTANDSSTUFEN` in `src/model/types.ts`; vorläufig bis BV-Bestätigung (offen in ARCHITEKTUR.md). |
| 2026-10-17 | **A2 WEP_Vorlage.xlsx in `public/`**: Kopie der Vorlage liegt in `public/WEP_Vorlage.xlsx` und wird über `/WEP_Vorlage.xlsx` ausgeliefert. Workbox-Precache auf `*.xlsx` erweitert. | Export-Tab lädt die Vorlage per `fetch('/WEP_Vorlage.xlsx')` wenn keine Bau-Excel hochgeladen wurde; die Datei muss im Service-Worker-Precache liegen, damit der Export auch offline funktioniert. |
| 2026-10-17 | **A3 Zahlenfelder als `type="text"` + `inputMode="decimal"` statt `type="number"`**; Einlesen über `leseZahl` (Komma oder Punkt, „1.234,5“), Anzeige über `zahlDe` (src/gruen/format.ts) | `type="number"` lehnt je nach Browser/Gerätesprache das deutsche Komma ab oder liefert leer zurück; `inputMode="decimal"` zeigt trotzdem die Zahlentastatur auf dem Handy. |
| 2026-10-17 | **A3 Bezeichnung für die Excel-Spalte „Art“ kurz und fachlich** (`kurzeBezeichnung`): gefundene Art aus `arten`/`synonyme` + Variantenmerkmale, Altersstufen gekürzt („5–30 J.“), Beispiel-Klammern entfernt; Feld bleibt immer editierbar | Die lange Katalog-Bezeichnung passte nicht in die Spalte und sagte nicht, welche Pflanze tatsächlich steht. |
| 2026-10-17 | **E2 Skizze als Bild:** PNG wird per XML-Patching als `oneCellAnchor`-Bild in das vorhandene Drawing des Blatts „Skizze Außenanlage-Aufwuchs“ eingefügt (Blatt über den Namen gesucht, nicht über `sheet19.xml`); Bildname „WEP-App Skizze“ zum Wiederfinden; das PNG erzeugt die App, der Export bekommt nur Bytes | Bleibt bei JSZip ohne weitere Bibliothek; Textfeld der Vorlage bleibt erhalten; Export bleibt in Node testbar (kein Canvas nötig); ein zweiter Export derselben Datei stapelt keine Bilder. |
| 2026-10-17 | **S2 Skizzen-Tab:** Editor bekommt seinen Startwert nur beim Öffnen des Tabs; Änderungen werden entprellt (400 ms) gespeichert, beim Verlassen des Tabs sofort; Export erzeugt das PNG (800×600) im Browser und gibt es an `exportWep` | Der SkizzeEditor setzt sich bei jedem neuen `wert` zurück (Auswahl weg) – ein fester Startwert vermeidet das; kein separater PNG-Download nötig, weil die Skizze direkt in der Excel landet. |
| 2026-10-17 | **Hosting der Beta: Cloudflare Pages** (`*.pages.dev`), automatischer Build bei Merge auf `main` | Kostenlos mit privatem GitHub-Repo (GitHub Pages bräuchte dafür einen bezahlten Plan), HTTPS für PWA-Installation und Microsoft-Anmeldung, kein eigener Server. |
| 2026-10-17 | **KI-Assistent über Google AI Studio (Gemini, kostenlos)** mit Modellkette und Fallback, Aufruf über Cloudflare Pages Function; bis zur rechtlichen Prüfung nur Fake-Daten (Plan: docs/KI-ASSISTENT.md) | Keine Claude-API vorhanden; Copilot-API (Vorschau, Lizenz je Nutzer, nur Text) passt nicht; KI liefert nur JSON, Preise/Stil rechnet die App – dadurch modellunabhängig. |
| 2026-10-17 | **KI-Testlauf (K-A0) unter `tools/ki-test/`**, Start mit `npm run ki-test` über **vite-node** (schon über Vitest installiert, eigene Mini-Konfiguration nur mit Alias `@`); Modellkette wird **nicht fest verdrahtet**, sondern aus `models.list` gefiltert, sortiert und per Probe-Anfrage mit `responseSchema` auf das Gratis-Kontingent geprüft; Antwortschema mit `katalogId` als Enum der Katalog-IDs; Prompt ohne Höchstwerte; Key nur im Header `x-goog-api-key` aus `.dev.vars` | vite-node löst den `@`-Alias auf, damit der Test den echten App-Code (`berechnePreisvorschlag`) rechnet; models.list sagt nichts über den Tarif, nur die Probe zeigt „limit: 0“; das Enum verhindert erfundene IDs; ohne Preise im Prompt bleibt „KI liest, App rechnet“ sauber getrennt; Key nie in URL/Logs. |
